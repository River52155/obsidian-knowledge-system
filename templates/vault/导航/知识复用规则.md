# 知识复用规则

本页只定义 用户 为什么会在未来重新打开一份知识。operation、权限、来源、目录和安全边界以 Vault 根目录 `AGENTS.md` 和 `导航/DeepSeek知识整理规则.md` 为准。

## 1. 五种使用意图

| intent | 未来的问题 | 主要产物 |
|---|---|---|
| `curiosity` | 为什么会这样？机制和例外是什么？ | question / concept |
| `viewpoint` | 这篇材料给我留下什么判断？ | source-summary / personal principle |
| `action` | 下次遇到类似情况怎么做？ | method / workflow |
| `self-understanding` | 我经历了什么，模式是什么？ | personal-record / reflection |
| `reference` | 它是谁、是什么、在哪里？ | entity / index |

前四种是主要使用入口；`reference` 是辅助地图。AI、认知、身体、关系等主题是第二层分类，不能替代使用意图。

## 2. 判断顺序

整理前依次回答：

1. 用户 未来在什么场景会重新打开它？
2. 打开后最需要得到解释、判断、步骤、自我理解还是定位信息？
3. 已有哪个页面承担同一用途？
4. 新内容是在补充原页面，还是回答一个独立问题？

一份材料可以包含多个意图，但必须有一个主要意图。只有真正需要独立调用的部分才拆成其他页面。

## 3. 各意图的最小结果

### curiosity

形成“现象 → 简短回答 → 机制链 → 例外 → 容易误解 → 相关概念”。

### viewpoint

形成“原文问题 → 作者主张 → 依据和例子 → 用户 明确认同的部分 → 适用边界”。没有 用户 明确表达时，不替 用户 写个人立场。

### action

形成“触发场景 → 前置条件 → 步骤 → 判断标准 → 失败情况 → 下次复用入口”。

### self-understanding

形成“发生了什么 → 当时观察和理解 → 可能重复的模式 → 当前更新 → 下次调整”。个人经验不直接升级为普遍规律。

### reference

形成简短实体或索引入口，说明它是什么、为什么相关、链接到哪里；不复制概念页正文。

## 4. 页面首屏

新建或实际更新的正式页面优先在标题后回答：

```markdown
## 这页回答什么

## 我什么时候会用到它

## 一句话结论
```

来源拆解页可把第三项改为“原文核心主张”。首屏的目标是让 用户 在十秒内判断这页是否解决当前问题。

## 5. 页面状态

- `inbox`：刚捕获，尚未整理。
- `draft`：已整理，但来源、覆盖、链接或例子仍不足。
- `usable`：未来可以直接理解或照着执行。
- `review`：来源冲突、过时或需要重新检查。
- `retired`：保留历史，但不再作为当前依据。

进入 `usable` 取决于是否减少未来的理解或行动成本，不取决于字数和排版整齐。

## 6. 拆页标准

不以固定字数作为唯一标准。只有以下情况才拆页：

- 一页同时服务两个以上互不相同的未来问题；
- 首屏无法说明页面用途；
- 页面中的某一部分需要被多个其他页面独立引用。

同一机制的连续步骤可以留在一页。不要把一份来源机械拆成大量孤立卡片。
