# DeepSeek 知识整理规则

> 本文件是 Karpathy-style LLM Wiki 在 用户 Vault 中的执行适配层。内容价值由 用户 决定；DeepSeek 负责保留、编译、连接和维护，不对 用户 主动交付的材料做道德筛选。

共同权限规则是 Vault 根目录的 `AGENTS.md`，遵守系统/平台约束和 用户 本次明确指令。本文件定义怎么执行知识 operation；`导航/知识复用规则.md` 只定义个人使用意图；`导航/知识体系设计稿.md` 只解释设计；上游 `llm-wiki` Skill 只作参考。

## 1. 先选择一个 operation

| operation | 作用 | 默认行为 |
|---|---|---|
| `ingest` | 按明确整理或保存请求，把来源编译进 Wiki | 授权范围内自动写入 |
| `compile` | 按明确请求重组一个 Wiki 范围 | 授权范围内自动写入 |
| `query` | 查找已有资料并回答 | 默认只读，不保存结果 |
| `lint` | 检查结构和来源健康 | 只报告 |
| `audit` | 处理 用户 对具体内容的纠错 | 默认只读说明，明确要求修改或保存后才写入 |

自然语言路由：

- “整理一下”“整理下来”“把这段保存下来”“保存到知识库”“收录这篇”“放进知识库” → 在目标明确时 `ingest`。只说“处理当前笔记”而未说明是解释、查找还是整理时，先澄清意图。
- “清理 / 合并 / 拆分 / 重组 Wiki” → `compile`。
- “根据我的知识库回答”“已有笔记里怎么说” → `query`。
- “检查哪里有问题”“检查知识库” → `lint`。
- “这里整理错了” → 只读检查与说明；“把这段改成……”等明确修改请求 → 写入型 `audit`。
- “只回答，不整理”“只查询” → 只读 `query`；不加这句话时，普通提问也默认只读。

普通聊天、情绪表达、知识提问、上传资料或@文件不会自动授权整理。不能因为答案有长期复用价值而保存，也不能为记录一次查询而写入 `outputs/queries/`、`gaps`、`audit` 或日志。随后明确说“把刚才的内容整理保存下来”才触发对应写入。

每轮只选择一个主要 operation。附带检查只能服务于主要 operation，不能借机扩大到无关页面。

## 2. 唯一目标是写入前提

目标解析顺序：

1. 用户 明确给出的 Vault 相对路径。
2. 用户 使用 `@` 提到的文件。
3. 当前 Claudian 会话明确绑定的笔记。
4. 用户 明确命名且只能匹配一个的 Raw 文件。

整理或修改请求如果不能得到唯一目标：

- 只问一个目标确认问题。
- 不搜索候选文件正文。
- 不根据“最近修改”“当前可见”或文件名相似度猜测。
- 不扫描或批量 ingest 整个 `raw/`。

只读查询可以检索多份相关笔记，不要求唯一写入目标。明确写入请求和目标都具备后，DeepSeek 可以说明 operation、intent、目标和预计动作，然后直接执行；这个说明不是批准闸门，也不能替代用户的写入请求。

## 3. 自动维护授权

只有 用户 明确要求整理、保存、收录，或修改、重组指定笔记后，才授权 DeepSeek 在对应范围内：

- 创建或更新来源拆解、概念、方法、工作流、问题、实体和个人记录页面；
- 合并重复页面、拆分职责混杂页面；
- 重命名或移动直接相关页面；
- 修复直接相关 wikilink；
- 更新 `wiki/index.md`、`wiki/gaps.md` 和当天日志。

单纯把资料放入 `raw/`、绑定笔记、提出问题或表示“这个有用”，均不授权这些写入动作。

不在自动授权范围：

- 修改 `AGENTS.md`、本规则、提示词、设计稿、Skill、脚本或插件设置；
- 永久删除知识；
- 读取或整理 `重要信息/`；
- 改写、覆盖、移动或删除已经存在的 Raw；
- 批量重写与本次目标无关的旧页面。

## 4. 来源处理与格式能力

### 4.1 Raw 是创建一次的来源层

- 已存在于 `raw/` 的材料直接读取，不改写。
- 材料尚未进入 `raw/` 时，先保存内容不变的稳定快照；之后该快照不可变。
- 作者观点、材料中的事实陈述、用户 明确表达的观点和 DeepSeek 推断必须分开记录。
- 用户 交付材料代表允许收录，不代表材料里的每个事实都已被外部验证；不确定性写清楚即可。

### 4.2 文件格式

- Markdown / TXT：直接读取。
- DOCX：先用稳定文字提取工具生成文字快照，再 ingest。
- 文本型 PDF：逐页提取文字，记录总页数、成功页和失败页。
- 图片型 PDF 或扫描页：没有可靠 OCR 时标记 `partial`，列出未处理页。
- 图片、表格、图表和排版承载关键信息但无法读取时，不得以正文推测替代。

### 4.3 来源拆解页的幂等字段

新建或实际更新的来源拆解页优先使用：

```yaml
---
type: source-summary
intent: curiosity | viewpoint | action | self-understanding | reference
status: draft | usable | review
sources:
  - raw/...
source_path: raw/...
source_sha256: <sha256>
ingest_status: complete | partial | failed
last_ingested_at: YYYY-MM-DDTHH:mm:ss
---
```

重复执行：

- 同一 `source_path`、同一 `source_sha256`、`complete`：复用原来源拆解页，不重复创建。
- 同一路径但 SHA256 变化：停止写入并报告 Raw 完整性异常。
- `partial` 或 `failed`：读取原页面的“未处理内容”，从缺口继续。
- 旧页面没有这些字段时，只有实际触碰才补，不做全库回填。

## 5. 先判断未来使用意图

| intent | 用户 未来为什么打开 | 主要产物 |
|---|---|---|
| `curiosity` | 搞懂为什么、机制和例外 | question / concept |
| `viewpoint` | 保留材料中的判断与启发 | source-summary / personal principle |
| `action` | 下次照着判断或执行 | method / workflow |
| `self-understanding` | 理解自己的经历和模式 | personal-record / reflection |
| `reference` | 知道它是谁、是什么、在哪里 | entity / index |

一份来源可以产生多个 intent，但先确定主要 intent。主题目录只是第二层地图，不能替代使用意图。

## 6. 页面类型和落点

### 来源拆解页：`wiki/summaries/`

保留：来源信息、原文问题、章节或论证结构、作者主张、关键事实、例子、因果链、含糊处、用户 的疑问和可提炼页面。

### 问题页：`wiki/questions/`

回答一个明确的“为什么、怎么回事、有什么区别”，包括简短回答、机制链、例外、依据、相关概念和待验证部分。

### 概念页：`wiki/concepts/`

解释可跨来源复用的机制、术语或模型，包括一句话解释、解决什么理解问题、机制、例子、容易误解和适用边界。

### 方法页：`wiki/methods/`

回答“下次遇到类似情况怎么判断或行动”，包括适用场景、前置条件、步骤、判断标准、反例和复用入口。

### 工作流页：`wiki/workflows/`

记录可稳定重复执行的流程，包括目标、输入、步骤、输出、验证、失败定位、恢复和下次触发方式。

### 实体页：`wiki/entities/`

人物、工具、项目、论文、机构的参考入口，不替代概念或方法页。

### 个人记录：`wiki/records/` 或现有合适目录

记录事件、观察、当时理解、重复模式、当前更新和下次调整。个人记录不因规则更新批量迁移。

## 7. 内容覆盖标准

整理来源时，先建立内容覆盖，再提炼知识。

必须保留：

- 原文提出的主要问题；
- 主要章节或论证步骤；
- 对理解结论有用的例子；
- 重要术语、比较、条件和因果链；
- 原文没有解决、表达含糊或互相矛盾的部分。

可以压缩：重复表达、无关格式噪声、不影响理解的口头过渡和重复例子。

不能把长材料只压缩成几句摘要；不能把未读取内容写成确定结论；无法覆盖的部分必须进入“未处理内容”。

## 8. 新建、更新和冲突

写入前搜索：同名页面、别名页面、相同来源拆解页和回答同一未来问题的页面。

- 同一概念的新证据、例子或边界 → 更新现有主页面。
- 同一主题但独立问题 → 新建问题页或子页面。
- 只对当前来源有意义 → 留在来源拆解页。
- 两个来源互相冲突 → 保留双方主张、来源和适用条件，不把后来的来源静默覆盖前者。
- 无法判断 → 写入 `wiki/gaps.md`，不创建含糊主页面。

同一材料换一种说法，不构成新概念。

## 9. 结构变化和轻量快照

以下动作前必须保存受影响文件的修改前版本和 manifest：

- 覆盖现有页面；
- 合并或拆分；
- 重命名或移动；
- 大范围重建索引。

单纯新建页面、追加日志、只读 query 和只报告 lint 不建立快照。

结构动作必须：

- 只处理与当前目标直接相关的范围；
- 同步受影响的 wikilink、`wiki/index.md` 和 log；
- 保留来源和恢复路径；
- 中途失败时停止后续写入，报告已完成与未完成，不伪造原子完成。

## 10. 各 operation 的执行

### ingest

1. 锁定唯一来源并计算 SHA256。
2. 检查是否已有同来源拆解页和 ingest 状态。
3. 完整读取可读取内容，记录未处理部分。
4. 建立或更新来源拆解页。
5. 提炼真正可复用的知识页；不机械拆成大量孤立卡片。
6. 更新 index、gaps 和 log。
7. 验证 Raw 指纹未变。

### compile

读取明确目标子树，按未来检索用途决定合并、拆分、移动或重命名；先建立轻量快照；不因排版偏好重排无关页面。

### query

只读查询执行 `导航/资料查询规则.md`，无需预载本写入协议；只回答、给实际使用的短标题来源与必要缺口，不写入知识、查询产物或日志。需要导航时才按需读取相关索引和页面。

用户 随后明确要求“整理下来”“保存到知识库”时，才把明确选中的内容交给写入流程；此时加载完整本规则并遵守来源、唯一目标和恢复协议，不把整段历史聊天当成保存范围。

### lint

检查唯一规则入口、歧义或坏链接、孤立页、index 覆盖、来源字段、Raw 完整性、日志形状和未完成 operation。独立 lint 只报告，不擅自修复。

### audit

把一条反馈对应到具体目标和锚点，先在聊天中说明检查结果。只有 用户 明确要求修改或保存该反馈时，才更新笔记、记录接受/部分接受/拒绝/延期及 resolution；不删除反馈历史。仅指出回答或笔记可能有错，不自动写入 audit 文件。

## 11. 完成标准

### ingest 完成

- 原文有稳定路径且指纹未变；
- 原文主要结构、观点、例子和因果链已覆盖；
- 可复用内容已连接到现有或新知识页；
- index 与 log 已更新；
- 没有明显重复页；
- `complete / partial / failed` 与实际读取范围一致；
- 未处理内容已明确列出。

### compile 完成

- 目标范围已按未来用途重组；
- 快照和恢复路径存在；
- 旧路径、wikilink、index 和 log 已同步；
- 没有永久删除知识。

### query / lint / audit 完成

- query 可追溯到实际检索、页面和来源，且未擅自写入任何知识文件、查询产物或日志；
- lint 列出具体位置且没有擅自修复；
- 只读 audit 在聊天中说明处理结论；已明确授权写入的 audit 保留反馈和处理记录。

## 12. 汇报格式

下列格式用于已授权的写入操作。普通问答只给答案、出处和必要缺口，不为填写格式创建页面或日志。

```markdown
## 本次处理

- operation：
- 目标路径：
- 实际读取的规则：
- 主要 intent：
- 来源 SHA256：
- 新建页面：
- 更新页面：
- 结构变化与快照：
- index / 链接 / 日志：
- ingest_status：complete / partial / failed
- 未处理内容：
- 恢复路径：
```

不要只说“整理好了”；报告必须能让 用户 找到结果、判断完整性并在需要时恢复。
