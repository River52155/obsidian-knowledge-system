# AGENTS.md

本文件是这个 Obsidian Vault 的唯一 AI 内核规则。Agent 进行知识整理、知识查询、Wiki 维护或系统规则修改前，必须先读取本文件。

## 0. 权威顺序与启动规则

规则冲突时按以下顺序处理：

1. 系统、平台与安全约束。
2. 用户 本次明确指令。
3. `AGENTS.md`：共同权限、目录、来源和安全边界。
4. 查询加载 `导航/资料查询规则.md`；明确写入才加载 `导航/DeepSeek知识整理规则.md`，并按需读取 `导航/知识复用规则.md`。
5. 上游 `llm-wiki` Skill 只作方法参考。

`导航/知识体系设计稿.md` 只解释设计，不是运行时指令。`导航/archive/` 是归档，不作为当前指令。

知识任务先读本文件，再分流：普通查询只读 `导航/资料查询规则.md`，按需检索目标和相关导航，不固定预读整个 Wiki 总索引。明确要求保存/整理/修改时，才读取完整写入规则和使用意图规则，按需检查 `wiki/index.md` 与直接相关页面。普通聊天无需加载知识写入流程。

## 1. 协作与授权边界

- Codex 或其他 Agent 修改本文件、提示词、设计稿、Skill、模板、导航和检查工具时，必须先输出只读计划；用户 在计划之后明确批准，才能执行。
- 普通提问、聊天、情绪表达、解释和知识查询默认只读：可以检索和读取相关资料并回答，不新增或修改笔记，也不写入查询产物、gaps、audit 或 operation 日志。
- 只有 用户 明确要求“整理一下 / 整理下来”“保存下来 / 记到知识库”“收录 / 放进 Wiki”，或明确要求修改、合并、拆分具体笔记时，才授权对应范围的知识写入。仅仅提出一个有长期复用价值的问题、上传材料、@文件或绑定当前笔记，都不等于授权保存。
- DeepSeek 只在上述明确写入请求的范围内自动创建、更新、合并、拆分、重命名和移动相关 Wiki 页面，并同步必要的索引、链接和日志，不需要逐项批准。
- 永久删除知识、修改系统规则、插件配置、API 配置或 `.obsidian/` 数据，不属于 DeepSeek 自动授权。
- “只回答，不整理”“只查询”等表达继续表示本轮不得写入；用户 不必每次补上这句话，普通问答本来就默认只读。
- Codex 默认维护底层逻辑，不主动读取或整理 Raw 正文，除非 用户 单独明确要求。

## 2. 五个 operation

| operation | 触发方式 | 默认行为 |
|---|---|---|
| `ingest` | 明确要求整理、保存、收录或放进知识库 | 授权范围内自动 |
| `compile` | 明确要求清理、合并、拆分或重组 Wiki | 授权范围内自动 |
| `query` | 提问、解释、查找或根据知识库回答 | 只回答，不写入 |
| `lint` | “检查哪里有问题”“检查知识库” | 只报告 |
| `audit` | 用户 对具体页面或段落提出纠错 | 先只读说明；明确要求修改或保存后才写入 |

知识写入同时需要明确的写入请求和清楚的目标、范围。`query` 不因答案有复用价值自动转为整理；用户 随后说“把刚才的答案整理保存下来”时，再处理明确的保存目标。“这个很有用”“以后可能用得上”不自动触发写入。

## 3. 目标解析

写入前的目标解析优先级固定为：

1. 用户 明确提供的 Vault 相对路径。
2. 用户 使用 `@` 提到的文件。
3. 当前 Claudian 会话明确绑定的笔记。
4. 用户 明确命名且能唯一匹配的 Raw 文件。

约束：

- 当前在 Obsidian 里可见的笔记，不等于当前会话已经绑定的笔记。
- “整理一下”只有在能解析出唯一目标时才直接执行。
- 没有唯一目标时，只问一个目标确认问题，不读取或修改候选文件。
- 不因为 `raw/` 中存在未处理文件，就自动扫描或批量整理整个目录。
- 多个候选项不得自行猜测。
- 只读查询可以检索多份相关笔记，不要求先确定唯一写入目标；上面的目标确认只用于整理或修改任务。

## 4. 目录与安全边界

- `raw/`：来源真相层。允许创建新的来源快照；文件一旦建立，不得覆盖、改写、移动或删除。
- `wiki/`：正式知识层，由 DeepSeek 自动维护。
- `wiki/index.md`：正式 Wiki 的唯一总目录，每个正式页面只列一次。
- `wiki/gaps.md`：缺证据、解析失败、未处理内容和暂时无法归类的问题。
- `log/YYYYMMDD.md`：operation 追加日志。
- `audit/`：人工反馈；处理后进入 `audit/resolved/`。
- `outputs/queries/`：仅在 用户 明确要求保存查询结果时创建产物；提升到 `wiki/` 也须在明确写入请求范围内。
- `archive/operations/`：仅保存覆盖、合并、拆分、重命名或移动现有页面前的轻量恢复快照。
- `重要信息/`：禁止 Agent 主动读取、搜索、引用、整理或输出正文。
- `.obsidian/`、`.claude/`、`.codex/`：只有 用户 对具体计划明确批准后才能修改。

不得读取、输出、复制或写入密码、API key、token、卡密、私钥、cookie 和其他凭据。发现疑似凭据时跳过正文，只报告路径和“包含敏感信息”。

## 5. 来源、幂等和失败状态

`raw/` 的语义是“创建一次，此后不可变”：

- 用户 已放入 `raw/` 的文件可直接处理。
- 当前材料尚未进入 `raw/` 时，先保存一份不改写内容的稳定快照，再进行 ingest。
- 文本无法完整读取时，允许完成明确部分，但必须把 `ingest_status` 标记为 `partial` 或 `failed`，并列出未处理内容。
- 不得把图片型 PDF、缺页、截断文本或推测内容声称为“完整整理”。

每个来源拆解页优先记录：

```yaml
source_path: raw/...
source_sha256: <sha256>
ingest_status: complete | partial | failed
last_ingested_at: YYYY-MM-DDTHH:mm:ss
```

重复执行规则：

- 同一路径、同一 SHA256、状态为 `complete`：复用原来源拆解页，不创建重复页面。
- 同一路径但指纹变化：停止并报告 Raw 被修改，不直接覆盖旧知识。
- 状态为 `partial` 或 `failed`：从未处理部分继续，并更新原页面。
- 旧页面不批量补字段；只有实际触碰时才渐进迁移。

## 6. 结构变化与恢复快照

只在以下动作发生前建立快照：覆盖现有页面、合并、拆分、重命名、移动或大范围重建索引。

- 单纯新建页面、只读查询、只报告 lint 和追加日志，不建立快照。
- 快照保存受影响文件的修改前版本和 manifest，不复制整个 Vault。
- 结构变化后必须同步 wikilink、`wiki/index.md` 和当天日志。
- 移动或淘汰页面时保留重定向、归档或明确恢复路径；不得永久删除知识。
- 中途失败时停止后续写入，记录已完成、未完成和恢复方式，不伪造成功。

## 7. 正式页面最小规范

新建或实际更新的正式页面优先使用：

```yaml
---
type: concept | source-summary | method | workflow | workflow-model | personal-record | question | entity
intent: curiosity | viewpoint | action | self-understanding | reference
status: inbox | draft | usable | review | retired
sources:
  - raw/...
---
```

正文首屏回答：

1. 这页回答什么。
2. 我什么时候会用到它。
3. 一句话结论；来源拆解页可改为“原文核心主张”。

页面类型、内容覆盖和完成标准由 `导航/DeepSeek知识整理规则.md` 定义；个人使用意图由 `导航/知识复用规则.md` 定义。

## 8. 默认执行流程

1. 按第 0 节读取运行时规则。
   普通聊天与只读 `query` / `lint` 到检索、回答、报告为止，不执行下列写入步骤，不创建快照、查询产物或 operation 日志。
2. 确定一个主要 operation、一个唯一目标和直接相关范围。
3. 搜索已有主页面、来源拆解页和入口索引。
4. 计算来源指纹；判断新建、更新、继续失败任务或停止。
5. 如果要修改现有页面，先按第 6 节建立轻量快照。
6. 执行内容整理和必要的直接相关结构维护。
7. 检查 Raw 指纹、链接、索引、来源和未处理内容。
8. 追加当天日志并返回实际变更报告。

用户 已明确要求写入时，执行前的范围说明不是批准闸门；DeepSeek 在该授权范围内说明后直接执行。不得把说明预计保存什么，当成 用户 已经要求保存。

## 9. 完成与报告

只读 `query` 只需给出答案、实际来源与缺口，`lint` 给出检查结果；它们不为满足汇报格式而新建笔记或日志。

已授权的写入 operation 不能只回复“完成了”。变更报告至少包含：

- operation 和目标路径；
- 实际读取的规则；
- 新建、更新、移动、合并或拆分的页面；
- index、链接和日志变化；
- 来源指纹与 Raw 完整性；
- `complete / partial / failed`；
- 未处理内容和恢复路径。

内容完整性、页面粒度和各 operation 的详细完成标准以 `导航/DeepSeek知识整理规则.md` 为准。
