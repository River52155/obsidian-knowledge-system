# Obsidian 知识系统

把来源保存、知识整理、检索回答分开。Skill 提供操作方法，不自带笔记、模型、索引、认证或正在运行的服务。

## 先识别环境与意图

确认用户的 Vault 和项目路径；不要照搬别人的绝对路径。已有安装先读 Vault `AGENTS.md`，检查当前 Git、服务身份、活动索引和实际模型。以当前源码、工具 schema 和现场状态为准，不把历史测试数当当前成功。

- 普通聊天、提问、上传或 @笔记：只读；不自动写 Wiki、日志或 gaps。
- 明确要求整理/保存：读 [知识整理](references/knowledge.md) 及 Vault 当前写入规则。
- 查笔记、跨月回顾、情绪交流：读 [查询与表达](references/retrieval.md) 及 Vault 当前查询规则。
- 安装、迁移、更新故障、插件定位或代码维护：读 [运行与验收](references/operations.md)。

先核对任务授权；用户已明确授权且目标清楚时直接推进，不为每个文件重复询问。写入目标优先采用明确路径、@文件、会话绑定笔记、唯一命名来源；窗口可见不等于会话已绑定。目标有歧义时只确认目标，不猜最近文件。

## 共同约束

- Raw 已存在的来源不可改写、移动或删除；Wiki 是可维护的知识页，索引是可重建的派生数据。
- 遵守 Vault 保护目录，不读取凭据，不把个人笔记打进 Skill 或上传包。
- 保存教程不等于理解、实施或有效；引文真实不等于结论正确；未检索到不等于全库没有。
- 按原问题的对象、范围、日期、用途查证，补查由证据缺口驱动，不能被第一条结果带偏。
- 附件提取和检索入库是两件事；不能把“Markdown 可查”说成其中图片也可查。
- 报告实际改动、实际验证和未完成项。区分程序测试、真实模型、原生界面验证；不以其中一种冒充另一种。

项目源码应包含 `personal-memory/`；三份当前提示源位于该目录的 `prompts/`。本 Skill 的参考文档描述契约，预算、版本、模型和部署参数应每次读取实际项目，不固定复制历史现场值。
