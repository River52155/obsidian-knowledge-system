# 原有知识整理流程

在已有 Vault 中先读 `AGENTS.md`；写入才加载 `导航/DeepSeek知识整理规则.md` 与 `导航/知识复用规则.md`。以下是迁移时的契约摘要，不覆盖目标 Vault 的当前规则。

## 分层

- `raw/`：稳定来源；新材料可创建内容不变的快照，已存在来源不可覆盖。
- `wiki/`：连接后的知识页，不是另存一份摘要。`wiki/index.md` 为正式总目录。
- `wiki/gaps.md`：已授权整理中的缺口；只读问答不写它。
- `log/`：已授权知识操作记录；`audit/` 保留纠错过程。
- `archive/operations/`：覆盖、合并、拆分、移动、重命名前的受影响文件快照与 manifest。
- 检索数据库与模型放在 Vault 外。Raw 默认不在当前检索范围，整理为允许目录里的 Wiki 后才可能被检索。

## 整理步骤

1. 确认明确写入请求和唯一来源。按问题/用途选择 ingest、compile 或写入型 audit；lint 和 query 默认只报告。
2. 检查现有来源拆解页与主页面，计算来源 SHA256。同路径同 SHA 且 complete 时复用；partial/failed 从缺口继续；同路径 SHA 改变先报告来源异常，不能覆盖旧知识。
3. 完整读取可读材料，保留论证结构、例子、条件、因果与矛盾；未读页、OCR 失败、截断明确记录，不能用短摘要冒充完整整理。
4. 先形成来源拆解，再提炼未来可复用的概念、问题、方法、工作流、实体或个人记录。以用途拆页，不机械按字数切碎。
5. 修改现有页前保存必要恢复快照。维护直接相关的 wikilink、index、gaps 和日志，不批量改无关页。
6. 核对来源指纹未变、页面覆盖、重复页、链接及恢复路径，报告 complete/partial/failed。

新建/更新来源页记录 source_path、source_sha256、ingest_status、last_ingested_at；正式页记录 type、intent、status、sources。沿用现有字段，不为统一格式重写全库。

## 使用意图

- curiosity：机制、例外和常见误解。
- viewpoint：作者观点与依据；用户是否认同必须有明确表达。
- action：触发场景、前提、步骤、判断标准和失败情况。
- self-understanding：事件、当时理解、可能模式与当前更新；个人经验不升级为普遍规律。
- reference：实体与链接入口。

页面首屏说明“回答什么、何时使用、核心结论”。保存知识的授权不等于允许修改系统规则、模型账户或插件配置。
