# 资料查询规则

本页只管只读 query。权限、目录和来源边界以 `AGENTS.md` 为共同规则；明确保存后才加载 `导航/DeepSeek知识整理规则.md` 的写入协议。

1. 理解问题：保留对象、时间、用途和用户当下需要。情绪表达先简短回应，再找贴切的支持/方法/记录；不能因命中严重主题就认定用户有该经历，不能凭少量片段判断固定人格。
2. 首查：需要旧资料时调用 personal-memory 的 search_notes，原问题可直接作query。普通查询无需预读完整整理规则、复用规则或整个Wiki总索引；需要导航才按需读相关入口。已通过“复制给AI”明确选中的有效材料先复用，不强制重复首查。
3. 补查：通常1–2次够用，最多3次是同一turn的工具内上限，不是必须凑数。沿用turn_id，purpose写清缺哪个对象/时间/方法/证据；不要被首个命中的主题带偏。返回NO_NEW_MATERIAL、SEARCH_LIMIT或TURN_BUDGET后根据已有证据回答或说明不足，不说全库没有。
4. 读证据：核对作者、时间和用途，必要时get_excerpt补上下文。文件目录、标题日期、修改时间都不自动代表作者/事件时间；摘录不等于认可，保存资料只证明存过，不能证明学过、理解、认可或实践有效；Wiki和其原始来源不算两份独立证据。
5. 核对：基于过去事实或笔记回答前，用verify_evidence核对本轮token和12–240字符连续逐字原文。只有实际返回区间可核对。某项失败时，只能根据verified中对应的已核对依据收窄答案，或用本轮原文修正引文后再核对；不得忽略rejected继续沿用未核对主张；区分原文事实、合理推断、一般建议和材料不足。检索是有限样本：只能说“本轮未找到带日期的实操记录”，不得说“你库里唯一”“没有任何记录”等全库断言；技术实践问题不引入无关的个人日记作为答案依据。工具不证明解释正确，提示词不能强制拦截最终输出。
6. 回答：先回应原问题。答案末尾仅列实际使用的来源短标题链接，同名加最短必要父目录。来源格式必须用 `[标题](verify_evidence返回的open_url)`，不用wikilink或路径作标签；正文中不重复插入同一来源链接。不要堆正文、表格、SHA、行号、类型或重复路径；搜索/核对/最终回答不要三次铺来源。明确“看原文/逐字引用”可以展示必要原文。
7. 保存：普通问题到回答为止，不写Wiki、Raw、gaps、audit、outputs或operation日志。“有用”不是保存授权；明确保存后再解析唯一目标，只处理指定内容，不把整段历史聊天一起收录。

每turn累计24000正文字元，按实际返回片段全文SHA去重；不同扩展上下文整段计费。闲置15分钟、128个驻留、重启失效；索引换版会明确使旧turn失效，沿用原问题省略turn_id重查，不能复用旧token。新问题或遗漏turn_id会新建；这些约束只作用于本机检索工具，其他已有写工具仍需遵守默认只读规则。
